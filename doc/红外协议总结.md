# 红外遥控三协议总结

## 1. 物理层基础

### 1.1 为什么需要载波

红外遥控的信号分两层：

- **载波**（38kHz / 40kHz）：通断闪烁，仅用于抗干扰。接收头内部有带通滤波器，只让这个频率的光通过，日光、白炽灯等直流/低频干扰全部滤掉。载波本身不携带信息。
- **包络**（envelope）：「什么时候有载波、什么时候没载波」的轮廓，**数据全在这一层**。

接收头（VS1838B / TSOP 系列）解调后从 OUT 脚输出的波形就是包络——它内部做完 38kHz 带通和检波，把载波剥掉了。

### 1.2 发送侧的信号构造

```
包络（数据层）
     ┌──────┐              ┌──────┐
     │ 560µs│    560µs     │ 560µs│         1690µs
    ─┘      └──────────────┘      └────────────────────────
      ├──── bit 0 ────┤            ├────── bit 1 ──────┤

LED 实际波形（把每段 mark 填成 38kHz 方波）
     ┌┐┌┐┌┐┌┐              ┌┐┌┐┌┐┌┐
    ─┘└┘└┘└┘└──────────────┘└┘└┘└┘└────────────────────────
      ↑ 约 21 个周期            LED 完全不亮
```

发送时构造包络、接收方直接拿到包络，载波在中间来回一趟就消失了。

## 2. NEC 协议

### 2.1 基本参数

| 项目 | 值 |
|---|---|
| 载波频率 | 38kHz |
| 基本单位 T | 560µs（严格讲 562.5µs，16T=9ms、8T=4.5ms） |
| 编码方式 | **pulse-distance**（mark 恒定、space 变长） |
| 数据长度 | 32 bit 固定 |
| 单帧时长 | 68ms（恒定，与内容无关） |
| 帧周期 | 108ms |

### 2.2 帧结构

```
引导码                    数据 32 bit                      停止位
┌────────┐        ┌─┐ ┌─┐   ┌─┐     ┌─┐
│  9ms   │ 4.5ms  │ │ │ │   │ │     │ │              ┌─┐
┘        └────────┘ └─┘ └───┘ └─────┘ └── … ─────────┘ └───────
  16T mark   8T       0  0    1      1                1T
```

- **引导码**：9000µs mark + 4500µs space（16T + 8T）
- **bit 0**：560µs mark + 560µs space（1T + 1T）
- **bit 1**：560µs mark + 1690µs space（1T + 3T）
- **停止位**：560µs mark（1T）
- **帧间隔**：补齐到 108ms 周期（~40ms space）

### 2.3 数据格式

32 bit = 8 bit 地址 + 8 bit 地址反码 + 8 bit 命令 + 8 bit 命令反码

反码用于校验，接收方核对 `Address ^ ~Address == 0xFF`。副作用是**帧长恒定 68ms**——不管发什么内容，32 位里永远是 16 个 1 和 16 个 0。

**Extended NEC 变种**：地址扩成 16 bit 不带反码，命令仍是 8+8 反码，总长还是 32 bit。

### 2.4 重发帧（长按键专用）

```
┌────────┐   ┌─┐
│  9ms   │2.25│ │
┘        └────┘ └────
```

9ms mark + 2250µs space + 560µs mark，只有 3 段、不带数据。每 108ms 发一次，接收方靠 2250 这个特征空隙认出「这是重复，不是新按键」。

## 3. AEHA 协议（日系家电协会）

### 3.1 基本参数

| 项目 | 值 |
|---|---|
| 载波频率 | 38kHz |
| 基本单位 T | 425µs |
| 编码方式 | **pulse-distance**（同 NEC，但时长更短） |
| 数据长度 | 48 bit 起，**无上限** |
| 单帧时长 | 46–87ms（48 bit）→ 可达 **300ms**（空调） |
| 帧周期 | ~130ms |
| 重发 | 通常 2 次 |

### 3.2 帧结构

```
引导码                  数据 48 bit 起          停止位 + 长尾空
┌──────┐      ┌┐ ┌┐  ┌┐   ┌┐
│3400µs│1700µs││ ││  ││   ││          ┌┐
┘      └──────┘└─┘└──┘└───┘└─ … ──────┘└──────────────────
  8T      4T    0  0   1    1           1T      ≥8ms
```

- **引导码**：3400µs + 1700µs（8T + 4T）
- **bit 0**：425µs + 425µs（1T + 1T）
- **bit 1**：425µs + 1275µs（1T + 3T）
- **停止位**：425µs mark（1T）
- **帧尾空隙**：**≥8ms**（AEHA 特有，比其他协议的停止位长很多）

所有时长都是 425µs 的整数倍，比 NEC 干净。

### 3.3 数据格式

最少 48 bit：

| 字段 | 位数 | 说明 |
|---|---|---|
| Customer code | 16 | 厂商码 |
| Parity | 4 | 厂商码四个 nibble 的异或 |
| Data0 | 4 | |
| Data1…DataN | 8×N | |

**这是空调协议的物理层。** 大金、三菱、松下、东芝、日立的空调遥控都跑在 AEHA 上，但每家在 Data 区自己定义私有格式和校验和——因为空调要一次传完模式、温度、风速、摆风、定时、节能等全部状态，帧能长到 **200–300+ bit**，单帧时长可达 300ms。

那 4 bit parity 只覆盖厂商码，跟 Data 区的校验和是两回事，后者是各家私有的。固件 API 应该收原始字节流 + 位数，不去理解语义。

## 4. Sony SIRC 协议

### 4.1 基本参数

| 项目 | 值 |
|---|---|
| 载波频率 | **40kHz**（不是 38kHz） |
| 基本单位 T | 600µs |
| 编码方式 | **pulse-width**（mark 变长、space 恒定） |
| 数据长度 | 12 / 15 / 20 bit |
| 单帧时长 | 12-bit: 17–25ms |
| 帧周期 | **45ms（从帧头起算）** |
| 重发 | 最少 3 次 |

### 4.2 帧结构

```
引导码            数据 12/15/20 bit
┌──────┐    ┌─┐   ┌────┐  ┌─┐
│2400µs│600 │ │600│1200│  │ │600
┘      └────┘ └───┘    └──┘ └── … ──
  4T     1T    0        1    0
       └─ mark 变长，space 固定 ─┘
```

- **引导码**：2400µs mark + 600µs space（4T + 1T）
- **bit 0**：**600µs** mark + 600µs space
- **bit 1**：**1200µs** mark + 600µs space
- **无停止位**，最后一个 bit 的 space 直接接帧间隔

### 4.3 数据格式

| 变种 | 组成 |
|---|---|
| 12-bit | Command 7 bit + Address 5 bit |
| 15-bit | Command 7 bit + Address 8 bit |
| 20-bit | Command 7 bit + Address 5 bit + Extended 8 bit |

### 4.4 Sony 的特殊点

1. **载波 40kHz**，切协议时必须重配定时器 ARR/CCR。好消息：600µs 在 40kHz 下正好 24 个载波周期，零量化误差
2. **pulse-width 编码**：mark 变长、space 恒定。跟 NEC/AEHA 正好相反
3. **无停止位**
4. **45ms 帧周期从帧头起算**，不是帧尾。12-bit 帧本体只有 17–25ms，所以实际间隔是 20–28ms 的变量。这跟 NEC/AEHA 的「固定帧间隔」逻辑不同
5. 最少连发 3 次，索尼设备普遍会丢掉单发帧

## 5. 三协议对比

| | NEC | AEHA | Sony SIRC |
|---|---|---|---|
| 载波 | 38kHz | 38kHz | **40kHz** |
| 基本单位 | 560µs | 425µs | 600µs |
| 编码 | pulse-distance | pulse-distance | **pulse-width** |
| 引导码 | 9000 / 4500µs | 3400 / 1700µs | 2400 / 600µs |
| bit 0 | 560 / 560 | 425 / 425 | **600** / 600 |
| bit 1 | 560 / 1690 | 425 / 1275 | **1200** / 600 |
| 停止位 | 560µs mark | 425µs mark + ≥8ms | **无** |
| 数据长度 | 32 bit 固定 | 48 bit 起，无上限 | 12 / 15 / 20 bit |
| 单帧时长 | 68ms（恒定） | 46–87ms → 300ms | 17–25ms（12-bit） |
| 帧周期 | 108ms | ~130ms | **45ms（从帧头）** |
| 重发 | 专用 repeat 帧 | 通常 2 次 | 最少 3 次 |
| 位序 | LSB first | LSB first | LSB first |

### 5.1 编码方式的核心差异

- **pulse-distance**（NEC / AEHA）：mark 固定，space 变长 → 逻辑「0」和「1」的区别在停顿时长
- **pulse-width**（Sony）：mark 变长，space 固定 → 区别在闪烁时长

所以编码器内部必须按 **(mark, space) 成对处理**，不能假设其中一个恒定——这样三种协议才能共用一套逻辑。

### 5.2 帧长跨度

| | 最短 | 最长 |
|---|---|---|
| 帧时长 | Sony 12-bit: 17ms | AEHA 空调: 300ms |
| 连发总时长 | Sony 12-bit ×3: 51ms | AEHA 空调 ×2: 600ms |

跨度近 **20 倍**。这是发送必须非阻塞的直接原因——AEHA 空调帧连发两次接近 600ms，期间 USB CDC 那边 100ms 的响应窗口不能停。

## 6. N32L40x 硬件实现架构

### 6.1 引脚与时钟

- **PA2** → TIM5_CH3（AF1 / AF6 / AF7 待确认）：载波输出
- **三个红外发射管并联接 PA2**：栅极 3×100Ω 并联 = 33Ω，下拉 3×100K 并联 = 33K
- **瞬间电流**：3×18mA ≈ 54mA 从 VDD_3V3 抽走，38kHz 通断，注意去耦
- **主频**：64MHz（HSE 8MHz × PLL），USB 模式可能降到 48MHz
- **TIM5 时钟**：APB1（64MHz 下 PCLK1=16MHz），是否有 ×2 倍频待示波器量一次 PA2 确认

### 6.2 双定时器架构

| 定时器 | 用途 | 时钟源 | 参数 |
|---|---|---|---|
| **TIM5** | 载波 PWM | APB1 | ARR/CCR 按协议切换 38/40kHz |
| **TIM6** | 包络计时 | APB1 | 2µs/tick，ARR 装当前段长度 |

### 6.3 载波参数

通式：`ARR = f_tim / f_carrier - 1`，`CCR3 = (ARR+1) / 3`

| TIM 时钟 | 38kHz (NEC/AEHA) | 40kHz (Sony) |
|---|---|---|
| 16MHz（无 ×2） | ARR=420, CCR3=140 | ARR=399, CCR3=133 |
| 32MHz（有 ×2） | ARR=841, CCR3=280 | ARR=799, CCR3=267 |

38kHz 误差 +0.01%，40kHz 零误差。接收头容差 ±5%，完全无影响。

### 6.4 包络定时器

**1 tick = 2µs**（不是 1µs，因为 16 位 ARR 上限 65.535ms，而 NEC repeat 帧的间隔可达 96ms）

- PSC：16MHz 下 31，32MHz 下 63，通式 `PSC = f_tim / 500000 - 1`
- 精度：560µs → 280 tick（0%）、425µs → 212 tick（-0.24%）、600µs → 300 tick（0%）
- 接收头容差 ±25%，2µs 比这细 75 倍，完全够用

### 6.5 载波开关方式

靠改 TIM5->CCDAT3：

- `0` = 关（CCR=0 则 PWM 恒低电平）
- `ARR/3` = 开（1/3 占空比）

比使能/禁用通道稳——后者可能让引脚停在高电平，MOS 一直导通，LED 直流点亮、不闪烁。

### 6.6 工作流程

1. `ir_send(fmt, data, nbits)` 立即返回，启动 TIM6
2. TIM6 更新中断（每段结束触发）：
   - 改 TIM5->CCDAT3 为 0 或 ARR/3（关/开载波）
   - 装下一段时长到 TIM6->AR
   - 递进状态机（引导码 → bit 0 mark → bit 0 space → … → 停止位）
3. 最后一段完成后关闭两个定时器，置 `ir_busy()` 为 false
4. 切协议时在定时器停止状态下重配 TIM5 ARR/CCR

**完全非阻塞**，300ms 的 AEHA 帧也不会卡住主循环。

## 7. 为什么不能用 USART IrDA

N32L40x 有 `USART_EnableIrDA()` / `USART_ConfigIrDAMode()`，但**不能用**：

1. USART IrDA 是 **SIR ENDEC**：它把每个逻辑 0 编码成 3/16 位周期的基带脉冲，**没有载波**
2. 消费级红外遥控（NEC / AEHA / Sony）要的是 **38/40kHz 载波被特定时长的突发和间隔调制**
3. USART 硬件生成不出「载波 + 任意包络」的波形
4. 每个 USART 只有一根 TX，本项目三个 MOS 并联到一根引脚，也只需要一路 PWM

## 8. 固件 API 设计要点

### 8.1 格式描述符表驱动

```c
typedef struct {
    uint16_t carrier_hz;                    // 38000 / 38000 / 40000
    uint16_t leader_mark, leader_space;
    uint16_t bit0_mark,  bit0_space;
    uint16_t bit1_mark,  bit1_space;
    uint16_t trailer_mark;                  // Sony 填 0 表示无
    uint16_t trailer_space;                 // AEHA 的 8ms
    uint16_t frame_period_us;
    uint8_t  repeat_count;
    uint8_t  period_from_frame_start;       // Sony 置 1
} ir_fmt_t;
```

图里的 `N` / `A` / `S` 三个字母正好可以直接当这张表的索引。

### 8.2 发送接口

```c
void ir_send(const ir_fmt_t *fmt, const uint8_t *data, uint16_t nbits);
bool ir_busy(void);
```

- 收**原始字节流**，不理解语义——因为空调协议（大金、三菱等）都是在 AEHA 物理层之上各自定义的私有校验
- AEHA 那个 4-bit parity（16 位 customer code 四个 nibble 异或）可以做成可选辅助函数
- LSB first，固件内部按位展开

### 8.3 缓冲策略

两种选法：

1. **预展开成 µs 数组**：AEHA 最坏 640 段 × 2 字节 ≈ 1.3KB RAM，好调试
2. **ISR 里现场生成**：按 {阶段, bit 序号, mark/space} 状态机，RAM 只需存字节流

长帧多的话选后者。

## 9. 待确认项

1. **PA2 的 AF 号**：TIM5_CH3 是 AF1 / AF6 / AF7，TIM2_CH3 是 AF2 / AF5，查数据手册另一张 pinmux 表确认
2. **APB1 定时器是否有 ×2 倍频**：示波器量一次 PA2，出 38kHz 就是无、出 19kHz 就是有
3. **三管并联是否产品有意为之**：发射时三路必定同时亮，没法按左/中/右分别选通
