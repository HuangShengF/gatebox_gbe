# GBE3 红外功能测试

## 1. 指令总览

| 方向 | Command | 名称 |
| --- | --- | --- |
| PC → MCU | `0x0402` | IR Transmission Request |
| MCU → PC | `0x1402` | IR Transmission Response |
| MCU → PC | `0x3402` | IR Transmission ErrorResponse |
| MCU → PC | `0x2401` | IR Receive Notification |

红外格式：`01=NEC`、`02=AEHA`、`03=Sony`。

## 2. 客户上位机测试数据

上位机的 `IR Transmission Request` 输入框只填写Payload，不填写帧头、Command、长度和CRC。

| 协议 | 可直接复制的Payload | 含义 | 红外接收板预期串口输出 |
| --- | --- | --- | --- |
| NEC | `0100FF1C08` | 地址`00 FF`，命令`1C`，Repeat=8 | `IR proto=1 bits=32 repeat=8 data: 00 FF 1C E3` |
| AEHA 48 bit | `0234121C00A55AC30D09` | Customer=`0x1234`，Data Bit Count=28，Data=`A5 5A C3 0D`，Repeat=9 | `IR proto=2 bits=48 repeat=9 data: 34 12 54 AA 35 DC` |
| Sony 12 bit | `031200340C03` | Address=`0x0012`，Data=`0x34`，Repeat=3 | `IR proto=3 bits=12 repeat=3 data: 34 09` |
| Sony 15 bit | `03A500350F03` | Address=`0x00A5`，Data=`0x35`，Repeat=3 | `IR proto=3 bits=15 repeat=3 data: B5 52` |
| Sony 20 bit | `033412561403` | Address=`0x1234`，Data=`0x56`，Repeat=3 | `IR proto=3 bits=20 repeat=3 data: 56 1A 09` |

接收板串口可能带时间戳，核对从 `IR proto=` 开始的内容即可。

正常发送完成后，上位机应收到：

```text
cmd=0x1402 IR Transmission (Response) payload=[]
```

## 3. Payload格式

```text
NEC：
01 + Address1 + Address2 + Command + Repeat Count

AEHA：
02 + Customer Code(2字节小端)
   + Data Bit Count(2字节小端)
   + Data(向上取整到字节)
   + Repeat Count

Sony：
03 + Address(2字节小端) + Data + Bit Count + Repeat Count
```

## 4. 普通串口助手测试

不使用客户上位机时，可以通过串口助手向USB虚拟串口发送完整协议帧。

串口助手设置：

```text
发送方式：HEX发送
接收显示：HEX显示
追加回车换行：关闭
定时发送：关闭
波特率：可保持115200，USB CDC实际不依赖波特率
```

注意：

- 客户上位机和串口助手不能同时打开同一个COM口。
- 建议关闭客户上位机、复位板子，再开始串口助手测试。
- 下列字符串必须按HEX字节发送，不能作为普通ASCII文本发送。

完整帧格式：

```text
Magic(2) + Sequence(2) + Command(2)
+ Payload Size(2) + Payload + CRC16(2)
```

多字节字段和CRC均为小端。

### 4.1 握手

先发送握手，否则红外请求会返回InvalidState。

握手Payload：

```text
0100000800000000
```

完整握手帧，Sequence=1：

```text
A5B30100010008000100000800000000911F
```

预期握手响应开头：

```text
A5B3010001103A00
```

当前固件完整握手响应：

```text
A5B3010001103A000100020000080000000048575F312E300000000000000000000046575F312E302E300000000000000000474245332D3030303030303031000000DF49
```

## 5. AEHA最大1280 bit测试

```text
Customer Code 16 bit + Parity 4 bit + Data 1260 bit = 1280 bit
```

上位机Payload组成：

```text
02 FFFF EC04 [157个FF] 0F 01
```

PowerShell生成无空格Payload：

```powershell
$payload = "02FFFFEC04" + (-join (1..157 | ForEach-Object { "FF" })) + "0F01"
$payload
$payload.Length / 2
```

字节数应为164。预期接收端显示AEHA 1280 bit，并在约2.18秒内完成，不能触发3秒超时。

## 6. 红外接收通知

接收板必须先完成握手，才能向PC发送 `0x2401` Notification。

| 协议 | Notification Payload示例 |
| --- | --- |
| NEC | `01 00 FF 1C 08` |
| AEHA | `02 34 12 1C 00 A5 5A C3 0D 09` |
| Sony 12 bit | `03 12 00 34 0C 03` |

Notification Sequence由设备产生，不要求等于发送板的请求Sequence。

## 7. 错误测试

错误响应为 `0x3402`：

```text
Error Code(2字节小端) + Error Detail(2字节小端)
```

| 错误码 | 名称 |
| --- | --- |
| `02 00` | InvalidPayload |
| `03 00` | InvalidParameter |
| `04 00` | InvalidState |
| `05 00` | Busy |
| `06 00` | InternalError |

### 7.1 非法Payload

| 项目 | 上位机Payload | 预期 |
| --- | --- | --- |
| NEC长度不足 | `0100FF1C` | InvalidPayload |
| NEC Repeat=0 | `0100FF1C00` | InvalidParameter |
| AEHA Data Bit Count=27 | `0234121B000000000000` | InvalidParameter |
| AEHA Repeat=0 | `0234121C00A55AC30D00` | InvalidParameter |
| Sony Bit Count=16 | `031200341003` | InvalidParameter |
| 未知Format | `0400000001` | InvalidParameter |

非法参数不能产生红外输出。

串口助手NEC Repeat=0完整请求，Sequence=7：

```text
A5B30700020405000100FF1C00F8BC
```

预期响应：

```text
A5B30700023404000300000024D6
```

### 7.2 Busy

1. 发送耗时较长的AEHA或较大Repeat请求。
2. 第一条未完成时立即发送第二条红外请求。
3. 第二条应收到 `payload=[05 00 00 00]`。
4. 第一条完成后再次发送，应恢复正常，不能永久Busy。

### 7.3 3秒超时恢复

仅在测试固件中，在 `IR_SendData()` 的 `IR_FrameStart()` 后临时加入：

```c
IR_FrameStart();
TIM_Enable(TIM6, DISABLE); /* 仅用于模拟TIM6异常 */
```

发送：

```text
0100FF1C08
```

约3秒后应收到：

```text
cmd=0x3402 payload=[06 00 00 00]
```

如果请求Sequence=2，对应完整错误响应为：

```text
A5B30200023404000600000011A8
```

再次发送不能永久Busy。测试完成后删除故障注入代码并重新烧录。

## 8. 测试顺序

1. 握手成功。
2. NEC Repeat=1、8。
3. AEHA 48 bit、最大1280 bit。
4. Sony 12、15、20 bit。
5. 检查接收板的协议、位数、数据和Repeat。
6. 测试非法Payload和非法参数。
7. 测试Busy以及第一条完成后的恢复。
8. 测试3秒InternalError恢复。
9. 多次Disconnect、Connect、重新握手后重复发送。

## 9. 当前待确认项

- Sony Repeat Count=0是否在发射前返回InvalidParameter。
- Sony Data bit7不为0时是否应该拒绝。
- AEHA最后一个数据字节的未使用高位是否应该拒绝。
- 大Repeat Count可能超过PC规定的10秒响应时间。
- 是否会收到本机红外LED产生的自身回波通知。

## 10. 通过标准

- NEC、AEHA、Sony正常发送均收到 `0x1402`。
- 接收板协议、位数、数据和Repeat Count正确。
- 非法参数收到 `0x3402`，并且不产生红外输出。
- 发送期间第二条请求返回Busy，完成后可以继续发送。
- TIM6异常时约3秒返回InternalError，后续不会永久Busy。
- AEHA最大1280 bit不会被3秒超时误判。
- 多次重新连接和握手后仍能正常收发。
